# 能力包使用说明与路由表

## 所有权

- 能力包由人类使用元提示词工作流手工生成、命名和维护。
- 本文件的路由表由人类维护；LLM 只读和执行，不得修改本文件或代写能力包。
- `capability-activation-log.md` 是唯一例外：常态下 LLM 只追加会话记录行；熵增整理时可按工作流规则压缩归档旧记录并保留统计摘要。不得改写本说明或能力包。
- 能力包是对脚手架不透明的文件：内容结构、格式、触发器和 `[[...]]` 引用均由人类决定。此处不提供包模板、不校验包格式。
- LLM 需要新增能力时，只能在 `open-questions-awaiting-human.md` 提出触发场景与期望能力簇，由人类决定是否制作。

## 路由表（人类维护）

只登记已经由人类创建且实际存在的包文件。“加载的能力包”使用标准知识链接 `[[文件名]]`，不带 `.md`；此脚手架不附带任何能力包，所以初始路由表为空。

| 任务类型 | 加载的能力包 | 可叠加能力包 |
|---|---|---|

能力包命名可采用“领域-能力本质”，例如 `architecture-thinking-and-tradeoff-reasoning`、`cpp-memory-model-and-ub-analysis`；示例名称不代表脚手架已附带这些包。

## 路由与激活规则

1. 人类点名某包时立即加载，优先于自动路由。
2. 未点名时，任务类型明确后按上表选择；加载后报告激活确认句，再开始使用。
3. 没有匹配包时不阻塞，使用基础能力执行，并报告“无匹配能力包”。
4. 同时激活最多 3 包。任务中途改变时，卸载不再适用的包，按新任务重新路由并再次确认。
5. 冲突优先级：`AI-AGENT-START-HERE.md` 硬规则 > 人类维护的能力包 > 脚手架默认行为。
6. 能力包通过文件加载，不依赖特定 Agent 产品的 system prompt 机制。
