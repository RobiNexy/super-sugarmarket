# 商品目录浏览与分类筛选

状态：Implemented
最后更新：2026-10-17

## 背景与问题

Sugarmarket 首个业务切片需要让演示者在本机浏览重建的小卖铺商品。视觉参考为 `human_files/template.html`：糖果色、手绘/蜡笔质感、分类药丸与 Emoji 商品卡；首版不使用真实商品图片。

## 目标与非目标

### 目标

- 从 FastAPI 商品目录接口读取可展示商品，并呈现商品名、文字描述、商品 Emoji 插画和人民币价格。
- 提供“全部”与商品分类筛选，切换分类后只展示对应商品。
- 处理加载、空列表和请求失败状态，并维持可爱、轻松的页面语气。
- 价格以元字符串（两位小数）从服务端获取并直接展示；数据库以分存储，转换在后端完成。
- 每张商品卡提供“加入购物车”，数量与购物车见 [[checkout-cart-and-order]]。
- 商品卡支持固定画布上的 Emoji 组合插画；可售为零时禁用加入购物车。
- 首版目录已有 100 种商品，分类数量符合下方分配。

### 非目标

- 本规格不包含结账、Transformer 调用、后台维护或商品编辑（分别见 [[checkout-cart-and-order]] 与 [[admin-backoffice]]）。
- 不加载远程商品照片；商品视觉由 Emoji/Emoji 组合承担，可无 Emoji。组合 Emoji 必须通过变形、叠放、裁切、折叠或嵌合形成一个整体图案，不能仅并排显示多个 Emoji（见 [[cute-ui-copy-and-motion]]）。

## 用户与领域规则

- 受众为项目作者的老同学与技术面试展示对象；应用在本机运行，不要求认证。
- 商品的可售规格拆成独立商品。
- 商品价格以人民币元字符串（两位小数）传输；前端只展示，不做浮点金额运算。
- 分类基于商品目录数据，并固定提供模板中的饮品、零食、泡面速食、日用品分类及“全部”筛选；某个基础分类暂时没有商品时仍可选择并显示空状态。

## 主流程

1. 用户打开商品页。
2. React 页面请求 FastAPI 商品目录接口。
3. 页面展示商品卡片及分类筛选。
4. 用户选择分类；页面只显示该分类商品，选择“全部”恢复完整目录。

## 边界与失败场景

| 场景 | 预期行为 |
|---|---|
| 目录仍在加载 | 显示轻松风格的加载提示，不显示伪造的成功数据 |
| 目录为空 | 显示友好空状态，不渲染空白错误布局 |
| API 请求失败 | 显示可重试的友好错误状态；不将失败误显示为“没有商品” |
| 商品没有 Emoji 标记 | 保留商品名称、描述与价格；不请求或显示真实图片 |
| 商品包含组合 Emoji | 在固定画布中渲染为一个整体插画；不把图层拆成并排字符 |
| 某分类无商品 | 分类仍可选择，并显示该分类的空状态 |
| 价格为元字符串 | 按人民币格式显示两位小数，例如 `"5.20"` 显示为 `¥5.20` |
| 商品可售数量为 0 | 卡片保留，加入购物车按钮禁用并显示可爱文案（见 [[cute-ui-copy-and-motion]]） |

## 验收标准

- [ ] Given 商品 API 返回多分类商品，When 用户打开商品页，Then 每张卡显示名称、描述、Emoji 插画（若有）及两位小数人民币价格。
- [ ] Given 当前选中“全部”，When 用户选择一个分类，Then 只显示该分类商品；选择“全部”后恢复所有商品。
- [ ] Given API 尚未返回，When 页面正在请求，Then 显示加载状态且不显示空状态。
- [ ] Given API 返回空数组，When 请求完成，Then 显示友好空状态。
- [ ] Given API 请求失败，When 请求完成，Then 显示错误和重试操作，不伪装成空目录。
- [ ] Given 商品价格为元字符串 `"5.20"`，When 前端渲染价格，Then 显示 `¥5.20` 且不进行浮点金额运算。
- [ ] Given 商品可售数量为 0，When 商品卡渲染，Then 加入购物车按钮禁用并显示可爱文案。
- [ ] Given 商品没有图片 URL 或 Emoji，When 商品卡渲染，Then 页面不发起图片请求并保留文字信息。
- [ ] Given 商品含两个或更多 Emoji 图层，When 商品卡渲染，Then 图层按变形与叠放参数组合为单个整体图案，不以横排 Emoji 字符替代。

每条验收标准须映射至少一个测试；测试文件意图块用 `@spec [[storefront-product-catalog-browsing-and-category-filter]]` 回链。

## 数据与接口

- 商品目录字段：稳定 ID、名称、分类、文字描述、可选简单 Emoji、可选组合 Emoji 描述、整数分价格、是否展示。
- API：`GET /api/products` 返回经 Pydantic 校验的可展示商品数组，字段和错误响应见 [[products-list-api]]。
- SQLite 商品表结构见 [[products-table]]；商品表字段已由人类批准。不从浏览器访问数据库。

## 目录扩充（第三切片）

- 目标：约 100 种商品，覆盖模板中的四类：饮品、零食、泡面速食、日用品。
- 每个分类的数量分配：饮品 25、零食 35、泡面速食 20、日用品 20。
- 每件商品包含：名称、分类、一句可爱描述、Emoji 插画（单 Emoji 或按整体构图设计的组合图案）、单价（元，0.00–99999.99，两位小数）、初始库存、`is_active = 1`。
- 组合 Emoji 须按 [[cute-ui-copy-and-motion]] 的画布与图层格式设计，利用重叠、形变、折叠或裁切构成新的整体造型；不得将多个 Emoji 简单并排作为组合插画。
- 内容以种子数据文件维护（如 `backend/app/seed/products.json`），启动时若表为空则导入。
- 商品内容由 Agent 起草，人类审核后合入；名称可为模拟的本地小卖铺商品，不使用真实品牌图片。
- 首次启动已有的 20 种模板商品保留，新增部分补足到约 100 种，不删除既有记录。
