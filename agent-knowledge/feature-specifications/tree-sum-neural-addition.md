# 购物车整数行的神经树形求和（tree_sum）

状态：Accepted（人类于 2026-10-15 指示实现）
最后更新：2026-10-15

## 背景与问题

[[adder-transformer-column-addition-training]] 训练的模型只能对固定 10 行、7 位有效数字的矩阵做一次竖式加法。结账时的行数可能超过 10，行值可能超过模型单批承载能力。`tree_sum` 按设计文档 `human_files/adder_transformer.md` §5 把任意多行的整数求和拆成若干批次：每批调用一次模型，低 7 位作为下一轮的行，高位由 Python 无损累加。

## 目标与非目标

### 目标

- 输入任意长度（0 行及以上）的整数行列表，每行 0..9,999,999，输出总和的神经计算结果。
- 每批调用一次 `OnnxAdder.predict`（或任何实现 `predict(matrix) -> (digits, carries)` 的对象）。
- 不足 10 行的批次用零行补齐。
- 输入非法（非整数、负数、超过 9,999,999、非一维）时抛出 ValueError，不调用模型。
- 空输入返回 0 且不调用模型。

### 非目标

- 不把神经结果与精确加法比较、不修正、不回退：差异诊断与三档展示规则属于结账层（见 [[open-questions-awaiting-human]] 中 Q-005、Q-008）。
- 不做金额换算（元/分）与表达式解析。
- 不保证精确：端到端精度由评估报告给出（见 [[tree-sum-accuracy-report]]）。

## 用户与领域规则

- 行值为整数分（或任意整数计量单位），范围 0..9,999,999。
- 模型输出数字经 argmax 得到 8 位数字，S = Σ d_i·10^i。
- 批次之间的整数拆分：低位 `low = S mod 10^7` 作为下一轮行，高位 `high = S div 10^7` 累加到 H。
- 最终结果 = H·10^7 + low_final。

## 主流程

1. 校验输入（类型、维度、取值范围）。空输入返回 0。
2. 当行数 > 10：按每 10 行一批调用模型，每批得到 S，写入 `low` 到新行列表，`high` 累加到 H；行数变为批数。
3. 行数 ≤ 10 时做最后一批：得到 S，`low_final = S mod 10^7`，`H += S div 10^7`。
4. 返回 H·10^7 + low_final。

## 边界与失败场景

| 场景 | 预期行为 |
|---|---|
| 空列表 | 返回 0，不调用模型 |
| 1–10 行 | 一次模型调用 |
| 11 行 | 2 次批量调用 + 1 次最终调用 |
| 10 行全为 9,999,999 | 一次调用，结果为 99,999,990 |
| 行值为负、超过 9,999,999、非整数 | ValueError |
| 非一维数组 | ValueError |
| 最终批次不足 10 行 | 用零行补齐 |

## 验收标准

- [x] Given 精确加法 oracle 模型，When 对任意长度（0–300）的随机行求和，Then 结果等于整数和。
- [x] Given 11 行、100 行，When 求和，Then 模型调用次数分别为 3 与 11。
- [x] Given 空列表，When 求和，Then 返回 0 且模型调用次数为 0。
- [x] Given 非法输入（负数、越界、浮点、二维），When 求和，Then 抛出 ValueError 且模型未被调用。
- [x] Given 10 行全部 9,999,999，When 求和（oracle），Then 结果为 99,999,990。
- [x] Given 训练检查点的 ONNX 模型，When 对少量购物车求和，Then 结果为有效整数并可复现（同输入同输出）。
- [x] 端到端精度见 [[tree-sum-accuracy-report]]：训练分布下 2 行精确、100 行精确命中率 97.75%（每组 2000 个购物车）；小额分布 100 行为 94.30%。精度已由人类接受（Q-009）。

## 数据与接口

- 代码入口：`backend/adder/tree_sum.py`，函数 `tree_sum(rows, model) -> int`。
- 结账层调用方式（2026-10-16 澄清）：结账先把订单的乘法全部展开为加法，得到加数列表（每个加数为单价的分值，重复 `数量` 次），再将整个列表交给 `tree_sum` 分批归并。`tree_sum` 本身不做乘法。
- 结账层容量上限：加数列表长度超过 `MAX_ADDENDS = 1000` 时拒绝结账（见 [[checkout-cart-and-order]]）；该上限不属于 `tree_sum` 本身，而是结账层的约束。
- 模型协议：`predict(matrix: np.ndarray) -> (digits [B,8], carries [B,8])`，实现类为 `adder.onnx_runtime.OnnxAdder`。
