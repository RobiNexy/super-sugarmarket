# 项目目的与范围

## 一句话

把大学课程设计中的小型网上小卖铺重做成专业、可本机演示的全栈项目，并训练 Transformer 完成购物车结账中的加法计算。

## 目标用户与核心场景

- 主要受众：项目作者的大学老同学，以及技术面试中的展示对象。
- 核心场景：演示者在本机浏览约百种小卖铺商品、将商品加入购物车、填写送货信息、完成结账并生成待处理订单；老板送货后在后台手动完成订单并管理商品与库存。
- 项目源自苏格公寓楼下 Sugarmarket 小卖铺的 Django 课程设计。原数据库已遗失；当年的结账无法正确完成，演示时曾把金额写死为 15 元。本项目旨在重建完整流程并展示更专业的工程实现。
- 可验证价值：不依赖真实支付即可端到端演示浏览、购物车、结账和订单查看；后台可管理商品与库存；结账计算按确认的 Transformer 设计运行。

## 范围

### 做什么

- 在一个仓库中构建 React + TypeScript 前端、FastAPI + Pydantic 后端、SQLite 数据库，以及 Transformer 结账计算能力；ADR 见 [[ADR-0001-react-typescript-fastapi-pydantic-sqlite-transformer]]。
- 提供商品浏览、购物车、结账及模拟下单的完整流程。
- 提供首版后台：管理商品和库存、查看订单。
- 重建约 100 种演示商品；商品保留文字描述，商品视觉使用 Emoji 或 Emoji 组合，不要求真实图片。组合 Emoji 通过变形、折叠、裁切、重叠与嵌合构成一个新的整体插画，不是把多个 Emoji 并排显示；具体组合描述格式见 [[cute-ui-copy-and-motion]]（Q-013）。商品规格仍拆成独立商品。
- 视觉方向采用可爱、糖果色、手绘/蜡笔质感；以 `human_files/template.html` 为风格参考，不要求逐字复刻其中未确认的交互。
- 每个可售规格视为独立商品；例如一瓶矿泉水和一箱矿泉水是两个商品，不建商品规格变体。
- 训练并使用 Transformer 执行加法；商品金额以人民币两位小数展示、内部转换为整数分，与 `human_files/adder_transformer.md` 的神经加法器设计一致。订单成交金额以 Transformer 输出为准，即使结果偏差很大也照此结账。Python/TypeScript 可以用普通加法计算对照差异，但不得改写模型价格或阻止下单。差异按三档展示（Q-008）：相对差异在 ±20% 内不提示；超出 ±20% 显示小标签“嘿嘿，神经网络有时候就是很神经”加 emoji；对照金额为 0 且模型金额非 0 时显示小标签“啥都没买你是怎么进来结账页面的？”（Q-011）；Transformer 返回 null 或推理报错时创建免单订单，显示小标签“神（经网络）赐予你免单”加颜文字。不显式展示差值数字。
- 订单在顾客结账后创建；老板在线下送达商品并收款后，手动在后台标记完成，标记完成时扣减库存。应用不处理支付或退货；退货由顾客线下下楼找老板处理。相关文案可用轻松可爱的语气，例如“退货请下楼找老板本人唠嗑～”。
- 后台不做认证。页面可显示演示用账户名“老板”和密码“123223”，但不校验凭据，也不作为访问控制。
- 全部组件在本机运行；首版不要求部署。

### 明确不做什么

- 不接入线上/真实支付。结账只创建待处理订单；老板线下送货收款后在后台手动标记完成，应用不集成微信支付或真实收款码。
- 不提供顾客或老板的身份认证与凭据校验；“老板”/“123223”仅为展示用默认信息。
- 不建立商品多规格/变体机制；不同规格拆成独立商品。
- 不支持应用内退货；由老板线下处理。
- 不依赖真实商品照片；首版使用 Emoji 视觉。
- 不把生产部署、多机服务或线上运营作为首版目标。

## 成功标准

- 演示者可在本机从商品浏览开始，完成购物车结账并创建订单，不依赖真实支付。
- 约 100 种重建商品可供浏览，具有文字描述并用 Emoji 或 Emoji 组合展示；金额统一以人民币两位小数呈现。
- 顾客可填写送货地点/联系方式并创建待处理订单；老板送货后能在无认证的后台手动完成订单，完成时库存相应扣减。
- 退货不经过应用；页面以可爱文案说明线下找老板处理。
- 结账金额必须直接采用 Transformer 输出的整数分结果；对照加法仅用于诊断，不回退、修正或拦截。相对差异超出 ±20% 时显示小标签提示；对照金额为 0 且模型金额非 0 时显示专用标签；Transformer 返回 null 或推理报错则免单（Q-008、Q-011）。详细模型边界与测试依据 `human_files/adder_transformer.md`。
- TypeScript 类型检查、Python 类型检查、测试和 lint 工具链确定后，后续交付按 [[workflow-rules-for-ai-agent]] 的三道验证门禁执行。

## 约束与假设

- 已确认技术栈：React、TypeScript、FastAPI、Pydantic、SQLite、Transformer；项目置于单一仓库并本机运行。详见 [[ADR-0001-react-typescript-fastapi-pydantic-sqlite-transformer]]。
- 开发者电脑已有 nvm 和 uv；其他工具链及具体版本尚待配置任务确定。
- 项目是怀旧/技术展示玩具，不要求线上生产部署；SQLite 与本机运行符合当前目标。
- 原始商品数据库遗失，演示商品需要重建；暂假设可建立新的演示目录，不要求恢复原数据库。
- 人类已提供单 HTML 前端风格模板和 Transformer 模型设计文档，分别为 `human_files/template.html` 与 `human_files/adder_transformer.md`；已读取，后续功能规格应以它们为输入。
- 预算和时间表尚未确认。
