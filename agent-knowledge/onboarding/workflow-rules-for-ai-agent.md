# AI 助手工作流规则

## 每次会话的标准流程

### 阶段 1：加载上下文

按 [[AI-AGENT-START-HERE]] 指定顺序读取必读文件，简报状态并确认本次任务。

### 阶段 2：理解意图与能力包路由

- 主动澄清歧义，每轮聚焦 2–3 个关键问题。
- 新需求确认对应的当前目标，必要时新增目标；续做任务从 [[task-board]] 的 In Progress 或 Ready 取卡。
- 人类点名能力包时立即加载；否则任务类型明确后按 [[HOW-TO-USE-THESE-PROMPTS]] 路由。
- 加载后必须说：“已加载 [包名]，将按其认知协议执行。”最多叠加 3 包。
- 中途换任务时卸载不适用包、重跑路由并再次确认。
- 无匹配包时用基础能力继续、不阻塞，并在会话简报和 [[capability-activation-log]] 记录“无匹配”。
- 发现缺包时，在 [[open-questions-awaiting-human]] 提出触发场景与期望能力簇；LLM 不制作、不修改能力包或路由表。

### 阶段 3：起草或更新规格

- 新功能在 `feature-specifications/` 新建结论明确的规格文件；改现有功能时同步规格。
- 架构选择先形成 ADR 草案并请人类确认。
- 大任务拆成自包含任务卡，放入 Ready 或 Backlog。
- 验收标准逐条映射至少一个测试。

### 阶段 4：写测试与代码

- 行为变更测试先行：先改测试表达新期望，再改实现。
- 按一次垂直切片推进；单次改动尽量不超过 5 个文件，超出时说明原因。
- 源文件意图块：`@purpose`、`@spec` 必填；核心业务文件填写 `@invariants`；涉及决策填写 `@adr`；有非局部影响填写 `@touches`。
- 测试文件意图块必须包含 `@purpose`、`@spec` 回链和 `@covers`，让规格覆盖可用 `rg` 查询。
- 类型法则见 [[coding-conventions-project-specific]]。

### 阶段 5：验证门禁（三绿）

**类型检查 + 测试 + lint 均通过才算完成。任一失败即任务未完成，修复后重跑。**

能力包规定的额外验证（例如 sanitizer 对照）也纳入门禁。若项目尚未配置其中某项工具链，应先把配置列为任务，不得把“未运行”报告为通过。

### 阶段 6：会话结束协议（强制）

结束会话前必须：

1. 更新 [[current-project-state]]：将关键变更置顶，最多保留 5 条。
2. 更新 [[task-board]]：完成项移入 Done，更新进行中进度和新任务。
3. 如有架构决策创建 ADR；未决问题追加到 [[open-questions-awaiting-human]]。
4. 检查本次修改文件的 `[[...]]` 目标；目标应位于 `agent-knowledge/`，根目录入口 `AI-AGENT-START-HERE.md` 是唯一例外。模板占位链接必须替换或删除。
5. 向 [[capability-activation-log]] 追加一行：日期 | 任务简述 | 激活包 | 路由方式（点名/自动/无匹配） | 结果备注。常态不得改写表头或旧记录；熵增整理时可按 §十一压缩归档旧行并保留统计摘要。
6. 若能力包的归纳触发器被触发，必须将结论落盘：ADR 候选入 ADR 草案，行动项入看板，风险入 open questions。
7. 输出变更简报。

影响面搜索统一使用 ripgrep（`rg`），例如 `rg -n -F '[[adr-filename' .`；测试覆盖查询使用 `rg -l -F '[[spec-filename' tests/`。不要改用 `grep`。

### 变更简报格式

```markdown
## 本次变更
- 影响：功能 / 规格 / 代码文件数 / 新 ADR
- 激活的能力包：[包名（路由方式：点名/自动/无匹配）；无匹配时说明]

## 需要你决策的点
- [ ] 问题；如有临时建议，说明理由

## 我不确定的地方
- 风险或尚未验证的假设

## 下一步
- task-board 已更新；建议下次从……开始
```

简报控制在 200–500 字，突出人类需要 review 或裁决的内容。

## 必须先征求人类意见

- 修改数据库 schema，尤其删除列或改变类型。
- 破坏性修改对外 API，或违反已接受的 ADR。
- 引入新的外部依赖、服务或持续成本。
- 涉及付费、发邮件或生产环境三方调用。
- 删除超过 3 个文件。
- 修改 `capability-prompts/` 中任何能力包或路由表；只能提出建议。

## 可自主执行

- 不影响接口的内部重构。
- 修复 bug 并补充回归测试。
- 更新普通项目文档、日志和 metrics；能力激活日志常态追加，熵增整理按规则归档。
