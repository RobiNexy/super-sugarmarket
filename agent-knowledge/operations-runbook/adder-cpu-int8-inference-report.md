# 竖式加法模型 CPU int8 推理报告

生成日期：2026-10-15<br>
CPU：Intel(R) Xeon(R) CPU E5-1650 v4 @ 3.60GHz；torch 2.11.0+cu128；量化后端 x86<br>
对应规格：[[adder-cpu-int8-inference]]；决策：[[ADR-0004-cpu-int8-inference]]

## 1. 操作步骤

1. 确认 fp32 检查点存在：`backend/checkpoints/adder/adder-final.pt`。
2. 在 backend/ 下执行（隐藏 GPU，确保 CPU 测量纯净）：
   ```sh
   CUDA_VISIBLE_DEVICES= uv run --group train python -m adder.cpu_deploy \
       --report ../agent-knowledge/operations-runbook/adder-cpu-int8-inference-report.md
   ```
3. 脚本依次执行：加载 fp32 → 转换为 CPU 推理图 → 用 65,536 条训练分布样本校准激活范围 → 静态量化 → 导出 `adder-cpu-int8.pt` → 从文件重新加载 → 三路精度评估 → 延迟/吞吐基准 → 写出本报告与 `deploy-summary.json`。
4. 验证：`uv run --group train pytest`、`uv run ruff check .`、`uv run --group train pyright`。

## 2. 量化方案

| 项目 | 取值 |
|---|---|
| 方式 | 静态 PTQ：校准得到固定 scale，运行时无范围统计 |
| 线性层 | 全部 10 个 nn.Linear（qkv、out、FFN 两层、两个输出头）→ fbgemm int8 GEMM |
| 权重 | int8 存储，每输出行对称 scale，取值限制在 [-64, 63]（fbgemm AVX2 饱和限制，见 ADR-0004） |
| 激活 | quint8 per-tensor 仿射，范围来自校准集 |
| FFN | 第二层输入与第一层输出共用 quint8 参数，ReLU 直接在 quint8 上执行 |
| 保持 fp32 | Embedding、LayerNorm、残差加法、softmax、注意力矩阵乘 |

## 6. 局限与未测项

- 测试机为 2016 年的 Broadwell Xeon（AVX2，无 VNNI）。在支持 VNNI/AMX 的 CPU 上 int8 的相对收益可能不同。
- 基准只测模型前向，不含调用方的 tree_sum、数据拼接与金额格式化。
- 小批量（batch=1）时延迟主要来自算子调度开销，int8 额外的量化/反量化算子会使其变慢。
- 整和准确率阈值 99.9% 已经 Q-010 确认；int8 不作为默认部署路径（见 ADR-0005），本报告仅作实验记录。
